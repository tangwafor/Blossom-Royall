# Contributing to Blossom Royall

## Before coding

1. Read `AGENTS.md` and identify the affected roles, routes, data, documentation, and tests.
2. Confirm that the change preserves mobile usability, localization readiness, tenant branding, and accessibility.
3. For database work, create a fresh schema snapshot before writing SQL.

## Definition of done

1. Every visible control performs a meaningful action.
2. Desktop and mobile rendered behavior tests cover the workflow.
3. Documentation and canonical inventory reflect the change.
4. Type checking, build, and tests pass.
5. The change is checkpointed with a clear commit message.

## Pull request review

Reviewers verify the user journey, tenant boundaries, authorization, persistence behavior, customer data handling, user experience, and release evidence.
